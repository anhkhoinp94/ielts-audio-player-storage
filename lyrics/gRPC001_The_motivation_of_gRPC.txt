Hello and welcome to Tech School. (Xin chào và chào mừng bạn đến với Tech School.)

In this course, we are going to learn about gRPC. (Trong khóa học này, chúng ta sẽ tìm hiểu về gRPC.)

And how to use it with protocol buffer. (Và cách sử dụng nó với protocol buffer.)

To develop an application in Go and Java. (Để phát triển ứng dụng bằng Go và Java.)

OK. Let's start with this simple question: (OK. Hãy bắt đầu với một câu hỏi đơn giản:)

What is the motivation of gRPC? (Động lực ra đời của gRPC là gì?)

Or, what's the problem that gRPC is trying to solve?
(Hay nói cách khác, vấn đề mà gRPC muốn giải quyết là gì?)

Well the answer is communication. (Câu trả lời chính là giao tiếp giữa các ứng dụng.)

Applications are written using different programming languages.
(Các ứng dụng được viết bằng nhiều ngôn ngữ lập trình khác nhau.)

For example, the back end can be written in Go. (Ví dụ, backend có thể được viết bằng Go.)

While the front end like the Android app is written in Java.
(Trong khi frontend như ứng dụng Android lại viết bằng Java.)

And iOS app is written in Swift. (Còn ứng dụng iOS thì viết bằng Swift.)

So how do they talk to each other? (Vậy làm sao để chúng giao tiếp với nhau?)

Today's trend is using micro-services architecture.
(Xu hướng hiện nay là sử dụng kiến trúc microservices.)

So even on the backend side, we might have many services written in different languages.
(Ngay cả phía backend, chúng ta cũng có thể có nhiều service viết bằng các ngôn ngữ khác nhau.)

Like Go, Python or Rust depending on the business needs and the technical constraints.
(Như Go, Python hoặc Rust tùy vào nhu cầu kinh doanh và ràng buộc kỹ thuật.)

So in order to communicate with each other, they must all agree on a set of API contracts.
(Vì vậy, để giao tiếp với nhau, tất cả phải thống nhất một bộ hợp đồng API.)

For instance: the communication channel, the authentication mechanism, the payload format, the data model, and how to handle errors.
(Ví dụ: kênh giao tiếp, cơ chế xác thực, định dạng dữ liệu truyền, mô hình dữ liệu và cách xử lý lỗi.)

There are so many things that need to be considered. (Có rất nhiều thứ cần phải cân nhắc.)

And that's why building an API is really hard. (Và đó là lý do xây dựng API là việc rất khó.)

More than that, we want the communication to be efficient.
(Không chỉ vậy, chúng ta còn muốn giao tiếp phải hiệu quả.)

By which I mean fast and lightweight. (Ý là phải nhanh và nhẹ.)

You know, the number of exchange messages between microservices are huge.
(Bạn biết đấy, số lượng thông điệp trao đổi giữa các microservice là rất lớn.)

So the faster communication the better.
(Giao tiếp càng nhanh càng tốt.)

Also, in some environment like mobile app, where the network speed and bandwidth is limited.
(Ngoài ra, ở một số môi trường như ứng dụng di động, tốc độ mạng và băng thông bị giới hạn.)

It's very important to have a lightweight communication protocol to interact with the server.
(Việc có một giao thức giao tiếp nhẹ để tương tác với server là rất quan trọng.)

Last but not least, we want the communication to be simple.
(Cuối cùng nhưng không kém phần quan trọng, chúng ta muốn giao tiếp phải đơn giản.)

Let's imagine that we are building a system that had hundreds or maybe thousands of micro-services.
(Hãy tưởng tượng chúng ta xây dựng một hệ thống có hàng trăm, thậm chí hàng nghìn microservice.)

We definitely don't want to spend most of the time writing codes only to enable them to talk to each other, right?
(Chắc chắn chúng ta không muốn tốn phần lớn thời gian chỉ để viết code cho chúng giao tiếp với nhau, đúng không?)

What we would like to have is some kind of framework that allow developers to focus on implementing the core logic of their services.
(Điều chúng ta muốn là một framework cho phép lập trình viên tập trung vào logic cốt lõi của dịch vụ.)

And leave everything else to the framework to handle.
(Và để framework xử lý mọi thứ còn lại.)

And, that framework is nothing else but gRPC. (Và framework đó không gì khác ngoài gRPC.)

OK, so now you've got some ideas about the problems that gRPC is trying to solve.
(OK, giờ bạn đã có ý tưởng về những vấn đề mà gRPC muốn giải quyết.)

In the next lecture we're going to learn exactly what gRPC is and how it works in order to achieve that goal.
(Trong bài học tiếp theo, chúng ta sẽ tìm hiểu chính xác gRPC là gì và nó hoạt động như thế nào để đạt được mục tiêu đó.)
