Welcome back! (Chào mừng bạn quay trở lại!)

In the last lecture, we know that gRPC was invented to solve the communication problem.
(Trong bài giảng trước, chúng ta biết rằng gRPC được phát minh để giải quyết vấn đề giao tiếp.)

So let's dive in to see how it works. (Vậy hãy cùng tìm hiểu cách nó hoạt động.)

What is gRPC? (gRPC là gì?)

It's a high-performance open-source feature-rich framework.
(Đó là một framework mã nguồn mở, hiệu năng cao và nhiều tính năng.)

Originally developed by Google and now is a part of the Cloud Native Computing Foundation (or CNCF), just like Kubernetes or Prometheus.
(Ban đầu được phát triển bởi Google và hiện là một phần của Cloud Native Computing Foundation (CNCF), giống như Kubernetes hoặc Prometheus.)

So what G in gRPC stands for? (Vậy chữ G trong gRPC có nghĩa là gì?)

At first, I thought it's Google. (Ban đầu, tôi nghĩ nó là Google.)

Yeah, you know why. (Bạn biết lý do mà.)

But in fact, it stands for different things in each gRPC release, such as good, green, glorious, and even gRPC itself.
(Nhưng thực ra, nó đại diện cho nhiều ý nghĩa khác nhau ở mỗi phiên bản gRPC, như good, green, glorious, và thậm chí là chính gRPC.)

You can check out the full list in this link.
(Bạn có thể xem toàn bộ danh sách ở liên kết này.)

OK, how about RPC? (Vậy còn RPC thì sao?)

Well, RPC stands for Remote Procedure Calls.
(RPC là viết tắt của Remote Procedure Calls (Gọi thủ tục từ xa).)

It's a protocol that allows a program to execute a procedure of another program located in other computer.
(Đây là một giao thức cho phép một chương trình thực thi một thủ tục của chương trình khác nằm trên máy tính khác.)

And what's awesome about it is that developers don't have to explicitly coding the details of the network interaction.
(Điều tuyệt vời là lập trình viên không cần phải lập trình chi tiết các tương tác mạng.)

It's automatically handled by the underlying framework.
(Tất cả đều được framework xử lý tự động.)

So in the client code, it looks like we are just calling a function of the server code directly.
(Vì vậy, trong mã phía client, trông như chúng ta chỉ đang gọi một hàm của server trực tiếp.)

And it works even if the codes on the client and server are written in different programming languages.
(Và nó vẫn hoạt động ngay cả khi mã phía client và server được viết bằng các ngôn ngữ lập trình khác nhau.)

Like in this example, the client code is written in Go and the server code is written in Rust.
(Ví dụ, mã client được viết bằng Go còn mã server được viết bằng Rust.)

Now, let's see how can gRPC do that.
(Bây giờ, hãy xem gRPC làm điều đó như thế nào.)

Basically, the client has a stub that provides the same method or function as the server.
(Về cơ bản, phía client có một stub cung cấp các phương thức hoặc hàm giống như phía server.)

The stub is automatically generated for you by gRPC.
(Stub này được gRPC tự động sinh ra cho bạn.)

The stub will call gRPC framework under the hood to exchange information with the server over the network.
(Stub sẽ gọi framework gRPC bên dưới để trao đổi thông tin với server qua mạng.)

And voilà! (Và voilà!)

Magically, everything just works. (Mọi thứ hoạt động một cách kỳ diệu.)

Thanks to the stub, the client and server now only need to care about implementing their core services' logic.
(Nhờ có stub, client và server chỉ cần tập trung vào việc triển khai logic dịch vụ cốt lõi của mình.)

We will see how the gRPC stubs are generated with the help of protocol buffer in the next lecture.
(Chúng ta sẽ tìm hiểu cách các stub của gRPC được sinh ra với sự hỗ trợ của protocol buffer trong bài giảng tiếp theo.)
